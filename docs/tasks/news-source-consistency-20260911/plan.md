# 실행 순서

1. 문서 22와 이벤트 19의 저장 식별자, 현 원문과 번역, RSS 실제 항목 식별자를 대조한다.
2. 원문 변화 후 파생 데이터 처리와 중복 수집 경로를 작은 fixture 및 실제 Postgres에서 재현한다.
3. 기존 이력을 훼손하지 않는 최소 변경을 구현하고 관련 parser/SQL/번역/연결 검증을 수행한다.
4. 운영 교정 대상 및 백업·검증 경로를 준비하고 허용 범위 내에서 적용한다. 코드·통합·배포·데이터 교정을 구분한다.

## 다음 독립 작업의 시작점

`/performance`와 `render_frontend_performance_outcomes_state_sql`은 지정 종료일의 attribution_run 및 보유 스냅샷에 정확히 연결된 결과만 보여준다. 전체 추천 outcome 복구가 이 화면에 자동 표시되지는 않는다. 후속 작업은 귀속 보고서의 기존 의미를 유지하면서 전체 추천 성과를 별도 조회 대상으로 제공한다. 종목/추천일/측정 기간/측정 종료일/벤치마크/표본 수를 함께 표시하고, 서로 다른 관측 기간을 하나의 평균 수익률로 합치지 않는다. 추천 상세로 돌아가 당시 점수·thesis·근거와 실제 측정을 대조하는 흐름을 완료 기준으로 잡는다.
