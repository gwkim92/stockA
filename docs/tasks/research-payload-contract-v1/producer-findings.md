# Producer findings and constrained patch method

The read-only audit run 34081521124 confirms normal field names and opaque source IDs already agree with the TypeScript consumer. Do NOT report a normal numeric-ID mismatch as a defect. The concrete defect is earlier coercion: _build_stock_equity_research_payload calls str on every scalar-list element, so malformed stored booleans/objects/numbers can arrive as plausible string claims. Its source list also calls _opaque_id without validating a positive database ID.

The patch preserves normal API fields and existing helper formatting. Malformed claim/source lists are rejected as a whole, and missing input is distinguished by explicit data_quality metadata. Existing API list/string shapes remain compatible; the company reader converts flagged missing/invalid fields to unknown for display. A true empty list remains explicitly empty. This is storage-to-presentation validation, not financial scoring or model/source entailment.

The adapter is 1.1 MB: connected fetch_file returned empty contents and raw fetch rejected it as oversized. The model container and Python runtime both fail with ClientError. A one-shot, branch-restricted workflow therefore stages only this known function's three-line change in a new unreferenced commit object. The adapter base blob is checked, AST comparison permits exactly one changed function, and no branch ref is updated by the workflow. The generated commit must be fetched and reviewed before the GitHub connector advances the feature ref. This is an explicit exception to connector-only object creation, not a grant to mutate main or deployment. The workflow holds temporary contents-write permission only for object staging and is removed before final integration. No token is printed, no production endpoint is called, and no model/database code is executed by staging.
