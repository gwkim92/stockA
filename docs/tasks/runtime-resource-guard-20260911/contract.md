# 반복 서버 무응답 복구와 빌드 보호

요청: 작업을 계속하고 서버가 반복해서 멈추는 원인을 확인한다. 앞선 자동화 활성화도 이어간다.

## 완료 기준

- 개인 계정/대상 인스턴스를 확인한 뒤 서비스 응답을 복구하고, 커널·빌드 로그와 자원 상태를 남긴다.
- 9월 10일/11일 서버 빌드 무응답과 이전 수집 대량 처리 문제를 구분한다. 확인하지 못한 OOM을 확정하지 않는다.
- 운영 경로와 EC2에서 프로젝트의 표준 `npm run build`가 컴파일 전에 중단되도록 실행 코드로 보호한다.
- 웹 소스 변경 시 CI가 Linux 빌드 결과물과 출처·해시 manifest를 자동 생성한다. 배포는 해당 결과물을 검증한 뒤 사용한다.
- 원래 자동 작업의 2회 실행과 실제 서비스/화면을 검증한다. 복구·배포·원인 확정·재발 방지 검증은 각각 보고한다.

## 경계

개인 계정 115623963546의 기존 인스턴스만 대상이다. AWS write는 인증된 Chrome 콘솔에서 수행한다. 인스턴스 증설·과금·IAM·보안 그룹·시크릿·실거래·추천 weight 변경은 하지 않는다. 자원 제한 수치는 복구 후 실제 사용량을 먼저 확인하며 추측으로 운영 작업을 강제 종료하지 않는다. 이미 CI 통과한 자동화 PR #62는 develop `fd8226630f3a9f26cdc7898e2e700239eac94f1d`로 병합했다. 아직 서버 배포는 아니다.
