# 실행 순서

1. 새 SSH와 개인 AWS 콘솔 상태를 확인한다. SSH는 banner timeout, 콘솔은 로그아웃이라 사용자 로그인을 요청했다.
2. 기다리는 동안 표준 빌드 진입점에 운영 호스트 차단을 넣고 기존 수동 CI artifact workflow를 웹 변경에 자동 실행되게 수정한다. manifest로 기존 activate.py와 연결한다.
3. 개인 AWS 로그인 후 대상 상태와 가능한 시스템 로그를 읽는다. SSH가 계속 불가능하면 해당 인스턴스만 재부팅해 복구한다. 종료/인스턴스 교체는 하지 않는다.
4. 복구 직후 커널 로그, 재부팅 기록, 메모리/swap/디스크, 프로세스별 사용량, 배포 staging과 실서비스를 확인한다. 현재 프로필의 중복 실행과 cgroup 제한도 읽는다.
5. 필요한 최소 자원 제한을 실측으로 정하고, CI가 통과한 소스·Linux 결과물로 배포한다. 임시 정지한 타이머는 원래 상태로 복원한다.
6. 새 재무 자동화 2회와 보호 데이터, API/웹, 다음 실행 시각을 확인하고 원인·완료·잔여 항목을 인계한다.
