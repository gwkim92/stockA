# 제품 평가 결함 수정

## 범위

사용자의 '작업해라' 요청에 따라 product-evaluation-20260910의 ISSUE-001~010을 수정한다. 전체 종목 탐색, 원천 문서 이동, 재무 입력의 기간 일치와 근거 보존, 실제 조회 상태의 표현을 먼저 해결한다. 이후 반복 카드·설명 압축, 문구와 모바일 표를 개선한다.

## 완료 기준

- 평가에서 사용한 운영 사례와 동등한 입력으로 기존 실패가 수정됐음을 확인한다.
- 첫 50개 밖 종목, 콜론 RSS ID, 실행 없음, 반복 미종결 티켓, 최신 결측+과거 계산값을 검증한다.
- 영향을 받는 Python/frontend 계약 및 단위 검사, 타입 검사, production build를 수행한다. 주요 변경은 실제 브라우저 데스크톱·모바일로 확인한다.
- 수정별 적용 범위, 테스트 결과, 운영 반영 여부, 남은 데이터 계보/재생성 범위를 QA·handoff에 기록한다.

## 경계

기존 사용자 문서 변경을 보존한다. API 키·인증·모델 선택·추천 weight·benchmark·성과 평가 기준·실거래는 변경하지 않는다. 재무 입력의 결측/오래된 값을 사실대로 취급하는 수정이며 새로운 투자 가정은 임의로 추가하지 않는다. 과거 저장 평가·리포트를 덮어쓰지 않는다. 운영 DB의 읽기 검증은 가능하지만 대량 재생성/배치 실행은 별도 구체적 범위를 정한 후 수행한다.

## 작업 순서

1. 재현·원인 확정과 입력 계약 정리.
2. 종목/원천/재무 입력 수정, 관련 회귀 검사.
3. 상태 표현·뉴스 지표·홈 중복·화면 밀도·모바일 수정.
4. 통합 검사와 현재 코드의 실제 화면 검증, 독립 리뷰.
5. 결과·미검증 영역·운영 반영 범위 인계.

## API와 계산 입력 계약

- `/api/stocks`: `q`는 최대 100자의 리터럴 검색이고 종목명·코드·시장에 적용한다. `scope=all|recommended|held|attention`과 함께 DB에서 먼저 필터링하고 기존 cursor/limit pagination을 적용한다. `stock_count`와 summary는 전체 active universe, `matched_stock_count`는 검색·scope 일치 수, 응답 stocks는 해당 페이지다. `attention`은 가격 없음/비양수 또는 조회일과 가격일 불일치다.
- 홈 `top_actions`에는 선택된 최신 `review_date`와 같은 종목/action/문제의 미종결 `occurrence_count`를 보탠다. 기존 open ticket 집계는 보존한다.
- 성과 `summary.excluded_weight`는 측정 대상이 없거나 제외 대상 비중 중 모르는 값이 있으면 null이다. `coverage_ready=not_evaluated`는 실행/대상 부족이며 통과가 아니다.
- 새 forecast는 `same_revenue_period_v1`과 원천/정규화 지표별 기간·상태·행 계보 및 기존 기본 가정 사용 목록을 저장한다. 현재 매출 기간과 계보를 확인할 수 없는 기존 forecast/FCF 기반 SOTP는 새 계산 입력에서 제외한다. 기존 저장 평가에는 이 한계를 표시하고 삭제하지 않는다.
