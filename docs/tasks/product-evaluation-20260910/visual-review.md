# stockA 독립 화면 평가

평가일: 2026-09-10. 판정: **REVISE — 기본 화면 체계는 안정적이나, 핵심 내용을 찾는 비용과 표현의 정확성을 개선해야 한다.**

이 평가는 주 평가자가 운영 웹에서 생성한 스크린샷과 DOM 관찰 기록을 읽은 독립 검토다. 이 검토자는 브라우저, 앱 소스, 운영 설정을 변경하지 않았다. 기능 실행 성공과 데이터 정합성은 주 평가의 재현 결과로 판단한다.

## 표본과 판단 범위

- 데스크톱 1440 × 1000과 모바일 390 × 844의 첫 화면을 각각 20개, 합계 40개 직접 확인했다: 홈, 시장, 테마 사이클 목록, 사이클 지도, 뉴스 리서치, 원천 뉴스, 기업 탐색, 투자 후보, 보유 검토, 판단 성과, 내 검토함, 가상 검증, 분석 근거, 분석 결과, 보류된 근거, 이벤트 분류, 데이터 상태, AI 운영, 거래 안전, 보완 작업.
- 증거: `artifacts/product-evaluation-20260910/screenshots/*-desktop.png`, `*-mobile.png`, 같은 이름의 `snapshots/*.json`과 `.txt`, `mobile-coverage.jsonl`.
- DOM의 문서 높이와 텍스트는 정보량·문구의 증거다. 화면 아래 전체 영역을 이미지로 확인했다는 뜻은 아니다.
- 색 대비 수치, 스크린리더 전체 흐름, 키보드 조작, 확대, 모션, 상세 페이지의 모든 상태는 이 독립 시각 검토에서 측정하지 않았다. WCAG 준수 여부를 단정하지 않는다.

## 개선이 필요한 사항

### V1 · P2 · 상단 설명·여백·반복 항목 때문에 실제 내용에 도달하는 비용이 크다

**관찰:** 분석 근거, 분석 결과, 이벤트 분류, 거래 안전은 상단 요약의 우측 카드 높이에 맞춰 좌측 제목이 아래쪽에 배치된다. 분석 근거 첫 화면에서는 제목 위에 넓은 빈 공간이 있고, 이어서 단계 카드와 읽는 순서 설명이 나온다. 거래 안전에서도 큰 빈 공간 뒤에 결론이 나타나며 상세 안전 조건은 1000px 첫 화면의 끝에서 시작한다. 분석 결과와 보류된 근거는 제목 다음에 같은 결론을 큰 문구로 다시 설명한다.

**영향:** 반복 사용자가 뉴스 근거나 차단 이유를 확인하기 전에 여러 설명 영역을 통과해야 한다. 같은 제품에서 기업 탐색·투자 후보는 첫 화면에 목록이 보이므로 작업마다 정보 밀도 차이가 크다. DOM 높이는 분석 결과 34,832px, 분석 근거 28,786px, 보류된 근거 21,078px다. 높이 자체를 오류로 보지는 않지만 긴 목록에 중복 설명이 더해지는 부담이 있다.

**권장:** 한 줄 결론, 핵심 수치, 필터와 목록 순으로 배치하고 읽는 순서·주문 경계의 자세한 설명은 접어서 제공한다. 상단 좌측 내용을 위쪽으로 정렬하고 요약 카드 높이를 줄인다. 목록 탐색은 점프 링크와 페이지 단위 이동으로 보조한다.

**증거:** `screenshots/evidence-desktop.png`, `results-desktop.png`, `classification-desktop.png`, `blocked-desktop.png`, `safety-desktop.png`; 각 DOM 기록의 `height`와 첫 화면.

모바일에서는 데스크톱의 좌측 여백이 줄어들지만 요약 카드가 길게 쌓인다. 뉴스 리서치·사이클 지도·분석 결과·분류·가상 검증의 390 × 844 첫 화면에는 요약과 이동 카드가 주로 나타나고 실제 근거 목록은 보이지 않는다. 모바일 문서 높이는 분석 결과 69,139px, 분석 근거 48,953px, 보류된 근거 40,251px, 가상 검증 23,141px다. 이 수치는 문서 길이의 관찰이며 모든 스크롤 영역을 시각 확인했다는 뜻은 아니다. 모바일에서는 요약을 더 압축하고, 목록 진입 링크·검색·페이지 단위 이동을 가까이 배치할 필요가 있다.

**같은 문제를 키우는 홈의 반복:** 아래 항목은 주 기능 평가의 홈 중복 문제와 겹치므로 별도 결함 수로 중복 집계하지 않는다.

**관찰:** 홈의 보유 논리 재검토 5개 항목은 TSLA, MSFT, TSLA, MSFT, TSLA 순이다. 같은 종목의 반복 항목에 관찰일이나 별도의 사건을 구별할 표식이 없다. 앞의 TSLA 2개는 동일한 비중 0.2883과 같은 조치 설명이다. 투자 후보 5개도 모두 “성과 검증 대기”이고, 한 설명 안에 “핵심 근거는 연결됐지만 성과 측정창이 아직 끝나지 않았다”와 같은 뜻의 문장이 연달아 나온다.

**영향:** 오늘 처리할 서로 다른 검토가 5개인지, 동일 검토의 이력인지 구분하기 어렵다. 홈에서 가장 중요한 종목 차이와 다음 행동을 읽는 데 도움이 되지 않는다.

**권장:** 종목·검토 사유 기준으로 묶고 최신 상태와 반복 횟수를 표시한다. 과거 항목은 날짜를 붙여 펼쳐 보게 한다. 공통 대기 문구는 섹션에서 한 번 설명하고 각 후보에는 종목별 근거와 다음 확인일을 남긴다.

**증거:** `screenshots/home-desktop.png`, `snapshots/home-desktop.json`의 `main`과 5개의 동일한 보유 검토 링크.

### V2 · P2 · 제목과 상태 문구가 근거보다 강한 결론이거나 해석하기 어려운 표현이다

**관찰:** 뉴스 리서치의 가장 큰 제목은 “339개 핵심 흐름이 시장 판단을 바꾸고 있습니다.”이고, 같은 화면의 뉴스 흐름 수치는 “규칙 기반”이라고 표시된다. 사이클 지도는 “AI 반도체 사이클 흐름이 현재 시장을 주도합니다.”라고 제목을 붙였으나 본문은 뉴스 강도·사이클 상태·하위 전파·추천 영향·충돌 신호를 합산한 순위라고 설명한다.

**영향:** 가장 눈에 띄는 문구가 내부 수집·연결 결과보다 강한 결론으로 읽힌다. 이 독립 검토만으로 해당 시장 판단의 참·거짓을 판정할 수 없지만, 화면이 제시하는 관찰과 해석의 경계가 제목에서 약해진다.

**권장:** “수집 뉴스에서 묶인 흐름 339개”, “현재 관측 점수가 가장 높은 흐름: AI 반도체”처럼 지표가 직접 뒷받침하는 제목을 사용한다. 시장 영향에 관한 해석은 근거, 기준 시각, 한계와 함께 별도로 제시한다.

**증거:** `screenshots/intelligence-desktop.png`, `cycle-map-desktop.png`; 해당 DOM의 제목과 지표 설명.

**함께 개선할 상태 문구와 번역:**

**관찰:** 판단 성과에는 `no outcome data`가 상태 제목과 설명으로 반복되고, 품질 게이트 설명도 영문 문장이다. 보유 검토에는 “보유 크기: within budget”, “현재 allocation policy 기준 안에 있다”가 표시된다. 판단 성과 DOM의 “보안 선택·테마 노출·현금 타이밍”은 투자 종목 선택을 설명하는 문맥에서 “보안 선택”으로 번역되어 있다. 홈의 테마는 영문 이름이고 다른 화면의 같은 영역에서는 한국어 이름을 사용한다.

**영향:** 한국어 화면을 읽다가 상태 해석을 다시 해야 하며, “보안 선택”은 투자 성과의 관점을 잘못 이해하게 할 수 있다. 모델 ID·공시 코드처럼 정확한 식별이 필요한 영문과 사용자 설명용 문장을 구별할 필요가 있다.

**권장:** 주요 상태는 “성과 측정 결과 없음”, “허용 비중 이내”처럼 한국어로 통일하고 원래 상태 코드는 상세에서 보인다. `security selection` 문맥은 “종목 선택”으로 고친다. 공통 테마명도 동일한 표시 이름을 사용한다.

**증거:** `screenshots/performance-desktop.png`, `portfolio-desktop.png`, `home-desktop.png`; `snapshots/performance-desktop.json`의 `main`.

### V3 · P2 · 성과가 비어 있을 때 다음 행동이 충분히 구체적이지 않다

**관찰:** 판단 성과는 “측정 추천 0개”, “미측정”, “미확인”과 “수신된 측정 결과가 없습니다”를 구분해 표시한다. 그러나 빈 결과 바로 옆에는 선택 날짜에 결과가 없는 이유, 결과가 있는 최근 기준일, 예정된 다음 측정일이 없다. 아래에 빈 커버리지·기간별 성과·행동별 성과·기여도 영역이 계속 나오며 “보완 작업” 링크는 마지막에 있다.

**영향:** 사용자가 날짜를 바꿔야 하는지, 표본 성숙을 기다려야 하는지, 수집 장애를 확인해야 하는지 결정하기 어렵다. 미측정과 0%를 분리한 정확성은 좋으나 빈 화면에서의 복귀 경로가 부족하다.

**권장:** 결과 없음 영역에 확인된 원인과 바로 할 수 있는 행동을 제공한다. 예를 들어 실제 데이터가 뒷받침할 때만 “최근 측정일로 이동” 또는 “다음 측정일 확인”을 보여준다. 미확인 상태라면 그 사실과 데이터 상태 링크를 제공하고 빈 하위 분석은 접는다.

**증거:** `screenshots/performance-desktop.png`, `snapshots/performance-desktop.json`의 전체 `main` 및 링크 목록.

## 긍정적으로 확인한 부분

- 주요 탐색 메뉴의 위치·활성 상태·아이콘 체계가 데스크톱 20개 화면에서 일관된다. 시장, 종목, 투자 후보, 보유 검토는 필터와 목록을 연결해서 배치한다.
- 모바일 20개 첫 화면에서 공통 상단과 하단 탐색 구조가 유지되고, 종목·보유 목록은 좁은 폭에 맞춰 재배치된다. 실제 메뉴 열기·하단 탐색 클릭은 이 검토자가 수행하지 않았다.
- 기준일과 “과거 기준”, “일부 결과”를 여러 화면에서 표시한다. 성과 화면도 미측정을 수익률 0으로 바꾸지 않는다.
- 투자 후보와 가상 검증 화면은 검토 대상과 주문 실행의 경계를 표시한다. 이 평가는 실제 주문 차단 코드의 성공을 대신 증명하지 않는다.
- AI 모델 설정 첫 화면은 현재 기본 모델, 변경 권한, 저장된 설정 번호를 구별한다. DOM에는 저장 모델과 최근 성공 호출 모델, 과거 `codex-cli-default` 기록을 분리한 설명이 있다.
- 내 검토함 빈 상태는 기업 탐색으로 돌아갈 링크와 저장 방법을 제공하고, 브라우저 저장이며 다른 기기와 동기화되지 않는다는 범위를 분명히 안내한다.

## 결론과 남은 범위

현재 첫 화면 표본에서 공통 셸의 붕괴나 한글 잘림은 관찰하지 않았다. 데스크톱 DOM 20개의 `overflows`는 빈 배열이었다. 모바일 19개는 문서 폭과 뷰포트가 모두 390px였지만, **데이터 상태는 문서 폭 406px / 뷰포트 390px**였다. `snapshots/health-mobile.json`의 넘침 목록은 “작업 / 최근 상태 / 성공·중단 / 최신 오류” AI 호출 상태 표와 ISO 시각 열을 가리킨다. 이 표는 첫 화면 밖이므로 해당 위치의 스크린샷·가로 이동 재현은 주 평가에 전달했다. 이를 모바일 전체 통과로 표현해서는 안 된다.

표본은 확대·키보드·문서 전체 접근성의 통과를 증명하지 않는다. 개선 우선순위는 실제 내용까지의 이동 비용, 판단 문구의 정확성, 미측정 상태에서의 다음 행동이다. 중복되는 기능 결함은 주 보고서와 한 번만 집계한다.
