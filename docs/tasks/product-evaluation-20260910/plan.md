# 평가 실행 계획

1. 운영 웹의 관찰 가능한 경로를 목록화하고 기능/화면 점검 표를 만든다.
2. 주 평가자는 실제 브라우저 흐름, API 읽기 결과, 데이터 시점과 화면 일관성을 확인한다.
3. 독립 검토자는 구현·테스트 관점에서 기능 경계와 누락 위험을 읽기 전용으로 확인한다. 화면 증거가 모이면 별도 시각 검토로 반례를 찾는다.
4. 관찰된 결함과 코드에서만 발견된 위험을 구분해 교차 확인한다. 재현되지 않은 위험은 확정 결함으로 세지 않는다.
5. 기능/화면 결과, 심각도, 증거, 우선순위, 점검하지 못한 범위와 인계를 작성한다.

## 종료 상태

1~5단계 완료. 최종 보고서와 QA·인계 갱신. 제품 수정은 평가 요청 범위 밖으로 남겼다.
