# stockA 기능·화면 종합 평가

평가일: 2026-09-10 · 운영 웹: http://127.0.0.1:13309 · 배포 `f9f1d5ee` · 소스 검토 `80769207`.

**판정: 리서치 자료를 읽고 개인 검토를 남기는 기반은 갖췄지만, 안정적인 투자 운영 도구로 보기에는 핵심 탐색과 데이터 의미의 보완이 필요하다.** 주요 화면은 모두 렌더링됐으나, 존재하는 종목을 검색하지 못하고 실제 원천 링크가 끊기는 문제가 있다. 미조회·미측정을 정상으로 표시하는 조건과 서로 다른 시점의 재무 입력도 우선 바로잡아야 한다.

## 범위와 판단 기준

주요 메뉴 20개를 데스크톱 1440×1000과 모바일 390×844에서 확인했다. 대표 상세 12개 경로, 메모의 작성·저장·복원·수정·삭제, 검색 실패, 원천 링크 실패를 추가 점검했다. 상세 중 검토 노트·전문 분석·평가 기록 3개는 모바일에서도 확인했다. 전체 회사·문서·날짜 조합을 전수 검사한 결과는 아니다. 정확한 경로·동작·증거는 [QA 기록](qa.md)에 있다.

독립 구현 검토의 관련 frontend 187개와 Python 25개 테스트, 합계 212개가 통과했다. 이는 현재 운영 데이터 조합이나 투자 성과의 유효성을 증명하지 않는다. 앱·모델·운영 설정은 변경하지 않았다.

## 우선순위

확정 결함·개선 항목은 **10개: High 3개, Medium 6개, Low 1개**다. High는 핵심 리서치 동선이나 계산 입력의 신뢰성을 우선 복구할 항목이다. Medium은 데이터 해석·검토 효율을 떨어뜨리는 항목, Low는 국소적인 표시 결함이다. 중복되는 독립 평가 항목은 한 번만 집계했다.

1. **먼저:** 종목 전체 검색(002), 원천 링크 복구(006), 재무 입력의 기간·최신성 통제(010).
2. **다음:** 미조회/미측정 판정 수정(003·005), 뉴스 지표 원천 수정(004), 홈 중복 정리(001).
3. **그다음:** 실제 목록 중심으로 화면 압축(008), 판단 문구·번역 정리(009), 모바일 표 수정(007).

각 수정은 현실적인 데이터 표본으로 통합 검증해야 한다. 50개 초과 종목, 콜론이 있는 RSS ID, 실행 없음, 반복된 과거 티켓, 계산 가능한 오래된 재무 행과 최신 미계산 행을 포함하는 검사가 필요하다.

- 기대/개선: `수집 뉴스에서 묶인 흐름`, `관측 점수가 가장 높은 테마`처럼 지표의 범위를 제목에 담는다. 상태는 한국어 설명으로 통일하고 기술 코드는 상세로 옮긴다. `security selection`은 이 문맥에서 `종목 선택`으로 수정한다.
- 증거: `screenshots/intelligence-desktop.png`, `cycle-map-desktop.png`, `performance-desktop.png`, `portfolio-desktop.png`와 해당 DOM. 독립 시각 평가 V2.

### ISSUE-010 — 최신 재무 모델에 오래된 계산 지표가 섞이고 추정 입력에 기간 제한이 없다

- 심각도: High · 데이터/계산 입력 · URL: `/stocks/NVDA/details`
- 재현: `최근 연간 재무 모델`은 12/14개 계산 완료로 표시한다. 2026년 지표 사이에 잉여현금흐름률 19.3%, CAPEX 부담 3.5%, FCF/순이익 132.6%가 **2012-01-29** 기준으로 나온다. 하단 2026-09-07 재무 추정 입력의 기준 FCF 마진도 19.3%다. 상단은 투자 판단 입력 가능, 부족한 근거 없음으로 표시한다.
- 코드 확인: 화면의 지표 선택은 최신 기간보다 계산 완료 상태를 우선한다. 실제 forecast 저장 SQL 역시 지표별 계산 완료 이력에 나이 제한·동일 기간 조건을 두지 않고 FCF 마진을 선택해 미래 FCF를 계산하는 경로가 있다. 독립 구현 평가 IMP-07 참조.
- 영향: 서로 다른 회계 시점의 숫자를 하나의 최신 기업 모델처럼 읽고, 오래된 현금흐름 특성이 추정에 쓰일 수 있다. 단순 번역이나 디자인 문제보다 먼저 통제해야 한다.
- 기대/개선: 모델별 기준 기간을 고정하고 입력 허용 연령·기간 일치·근거 계보를 검사한다. 최신 지표가 없으면 누락/오래됨으로 남기고, 대체 지표 사용은 명시적인 상태와 근거를 붙인다. 관련 가치평가 입력도 함께 재검토한다.
- 증거와 한계: `screenshots/issue-010-financial-periods.png`, `snapshots/detail-financial-desktop.json`, 대응 모바일 DOM, 독립 구현 평가 IMP-07. 운영 DB의 특정 2012년 행→현재 forecast 행 연결은 직접 조회하지 않았으므로 정확한 행 계보는 미확정이다. 화면의 값 일치와 코드의 선택 구조를 구분한다. 외부 공시 수치 자체의 정확성은 감사하지 않았다.

## 성능·데이터 준비 관찰

- **반복 로딩 지연:** 뉴스 리서치의 DOMContentLoaded는 데스크톱 18.8초·모바일 17.1초, 데이터 상태는 15.3초·15.2초였다. SSH 터널과 당시 서버 상태를 포함한 두 번의 실제 관측이며, 사용자 전체의 Core Web Vitals나 순수 백엔드 처리 시간은 아니다. API별 시간을 재서 병목과 부분 실패 격리를 확인할 필요가 있다.
- **운영이 떠 있음과 데이터가 준비됨은 다르다:** 점검 당시 API·웹·공개 웹 서비스 3개와 타이머 13개가 active였다. 현재 조회일의 성과 측정 추천은 0개이고, 보유 화면의 성과 연결은 0%다. 일부 가격·전문 자료와 위험 정책은 오래된 기준일이 표시된다. 현재 AI 모델 설정을 바꿨다는 사실도 모든 과거 리포트가 새 모델로 재생성됐음을 뜻하지 않는다.
- **AI 입력 자료의 한계:** CNM 표본은 RSS 게시자 요약이 없고 제목 중심 해석임을 명시한다. 기업 검토 NVDA 리포트는 규칙 기반·검증용 제공자 기록이다. 화면 기능의 존재를 전문 기업 분석의 완성이나 수익성 검증으로 바꾸어 해석하면 안 된다.
- **성과 빈 상태의 다음 행동:** 결과가 없는 날짜에서 왜 없는지, 최근 측정일이 언제인지, 기다릴 시점이 언제인지 바로 알기 어렵다. 005를 수정할 때 확인된 원인과 최근 측정/데이터 상태로 이동할 동선을 함께 제공하고 빈 하위 분석은 접는 편이 좋다.

## 잘된 점과 디자인 판단

탐색 메뉴·활성 상태·기본 글꼴·색 체계가 주요 화면에서 일관된다. 투자 논리, 반대 근거, 무효화 조건, 원천 자료와 평가 이력을 따로 읽을 수 있는 구조가 있다. 개인 노트는 저장 범위를 설명하며, 평가 이력은 과거 기록과 현재 자료를 구분한다. 실제 작업별 AI 모델 설정은 저장 모델·CLI 선택·최근 성공 호출·과거 DB 기록을 구분하는 방향이 적절하다.

디자인은 일관된 기본 셸을 갖췄지만, 일부 화면의 큰 선언형 제목·반복 요약 카드·과도한 안내는 업무 화면보다 소개 화면에 가깝다. 전면적인 스타일 교체보다 실제 항목과 차이를 먼저 보여주도록 정보 배치를 정리하는 것이 우선이다. 자료 부족을 0% 수익률로 바꾸지 않는 좋은 표현도 있지만, 003·005·010처럼 준비 상태의 의미가 어긋나는 곳을 함께 바로잡아야 한다.

## 미검증 범위

모든 종목·문서·시점의 수치 정확성, 외부 원천과의 재무 대사, 전체 투자 계산/백테스트, 복구·부하·장시간 운영, 실거래 실행, 스케줄러 새 회차의 성공, 모든 모델의 현재 실제 호출, 모델 변경 저장 권한의 이번 재실행은 검증하지 않았다. 화면 전체의 WCAG 준수·스크린리더·확대/모션·모든 키보드 흐름도 미확인이다. 사용자 Chrome의 인증·설정과 운영 데이터를 유지한 채 읽기 중심으로 평가했다.
