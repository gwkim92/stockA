# 변경 검토

maintenance 성공 시각 조회를 보고서가 이미 쓰는 latest_source_sql과 공유했다. 기존 같은 정책의 atomic source receipt/SHA가 있는 경우 상태는 보존된다. 기존 legacy upsert가 새 보고서의 검증 가능한 원천이라는 주장을 만들지 않고, 동일한 제한 수집 경로에 다시 들어가도록 했다.

새 테스트는 실제 Postgres에서 원인과 유효 receipt 획득 후 종료 조건까지 검증한다. running 결과 대조, failed24시간 대기,7일 갱신,ETF 제외,일회3종목 제한이 유지된다. 모델 호출 수/리포트 예산, 기간 정책, DB schema, 평가 기준은 변경하지 않았다.

운영 수집은 한 번만 실행했고 같은 상태 재실행은 결과0개였다. 다른 회사 재무, 대상 회사의 과거 정규화 자료, 추천/점수/보유/benchmark/성과/리포트 hash를 대조했다. 이는 독립 에이전트 검토가 아닌 자체 검토 및 실제 검증이다.
