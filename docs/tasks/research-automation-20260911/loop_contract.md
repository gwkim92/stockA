# 반복 실행 계약

- 6시간마다 최대 3개 기업의 SEC 원천을 점검한다. 신규/구정책/오래된 수집 순서로 처리한다.
- 정상 갱신 간격은 7일, 실패는 최소 24시간 후 재시도한다. 영구적 원천 한계도 주기적으로 재확인하되 다른 종목 처리를 막지 않는다.
- HTTP는 직렬로 처리하고 요청 간 간격을 둔다. 모델 설정과 기존 일일 보고서 최대 5개 범위를 유지한다.
- 현재 기준일 snapshot만 생성 또는 명시적 현재일 갱신하며 이전 날짜의 정규화는 보존한다. 재수집 전 원천과 현재일 snapshot을 같은 서버에 보존한다.
- 운영 psql은 Docker 내부에서 실행된다. 원본/현재일 정규화의 변경 전 값은 같은 DB의 해당 child run `config_json.backup_before`에 보존하며 외부로 내보내지 않는다. 공개 SEC 응답은 서버의 전용 artifact 디렉터리에 저장한다.
- 진행 중 또는 결과 불확실 상태는 재수집하지 않는다. child run 행의 잠금을 잡아 원천·정규화·성공 상태의 단일 transaction 커밋을 확인한다. 여전히 잠겨 있으면 대조 대기, 잠금이 풀린 running이면 전체 rollback으로 판단하여 failed와 24시간 대기를 기록한다.
- 성공/실패/대기/결과 확인 필요를 분리한다. 모든 대상이 성공하지 않았는데 전체 정상으로 표시하지 않는다.
