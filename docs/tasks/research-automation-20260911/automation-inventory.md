# 서비스 자동화 현황과 후속 순서

기준: 2026-09-11 운영 EC2와 현재 코드. 6월 문서의 완료/대기 수치를 현재 상태로 간주하지 않는다.

| 데이터 상태 | 타이머/파이프라인 이력 | 새 자동 갱신 job을 API·실행 이력에 추가. API에는 남은 큐·최근 대상·재시도 정책 노출 |

운영 읽기 점검에서 추적 기업 32개 중 기존 정책+정규화 갱신 3개(ARM/AAPL/NVDA), 대상 29개를 확인했다. 전체 상장 종목에 무제한 요청하지 않는다. 1회 최대 3기업이므로 대기 목록은 여러 주기에 나누어 처리한다.

## 자동 처리와 사람의 판단 경계

- 데이터 재수집·정규화·상태 검증·실패 재시도는 서비스가 담당한다. 모델은 기존 UI 설정과 인증을 사용한다.
- 새 자동 검사 결과를 과거 보고서의 사람 검토/승인으로 기록하지 않는다. 기존 ARM/AAPL/NVDA 보고서의 원천 교정 필요 표시는 새 보고서가 생성되기 전까지 남는다.
- 계정 로그인·추가 권한 동의는 서비스가 사용자를 대신해 승인할 수 없다. 만료 감지와 후속 알림은 자동화할 수 있다.
- 실제 주문과 추천 weight 변경은 기존 별도 승인 경계를 따른다. 이번 요청을 실거래 자동화 승인으로 해석하지 않는다.

## 다음 구현 계획

0. **완료: 운영 복구와 배포 자원 보호**: 이번 분리 빌드 도중 발생한 웹·SSH 무응답을 먼저 복구한다. 원인은 로그로 확인하며, 앞으로 운영 서버에서는 빌드하지 않고 자원 제한을 둔 별도 Linux 환경의 검증된 결과물만 활성화한다. develop 502eb679 배포, 실제 자동 수집 2회/6기업과 원래 타이머 복원, Chrome 실행 이력 확인까지 완료했다. 다음에는 현재 infinity인 배치/DB 자원 한도와 무진행 감시를 실제 실행량 기준으로 설계한다.

1. **전문 분석의 원천 변경 전파**: 새 SEC 수집의 성공 영수증을 기준으로 재무 예측·피어·사업부·밸류에이션·보고서 입력을 필요한 종목만 다시 계산한다. 현재 자동화는 원천과 재무 정규화를 즉시 갱신하고, 나머지 전문 분석은 기존 주간 작업을 따른다. 새 입력 manifest와 보고서의 원천 버전을 연결한다.
2. **보고서 근거의 자동 검사**: 수치·회계기간·원문 링크·누락 근거를 규칙으로 검사하고, 통과/제한/차단과 이유를 사용자 화면에 노출한다. 문장별 판단을 사람이 승인한 것으로 표시하지 않는다. 필요한 AI 검사도 기존 예산 안에서 작업별 한도를 둔다.
3. **일일 전체 작업의 재개 처리**: 각 단계의 입력 버전과 완료 영수증을 저장하여 일시적 장애 뒤 이미 완료된 단계를 건너뛰고 재개한다. 현재 재무 전용 작업의 원자적 복구를 가격·뉴스·분석으로 확장한다. 주문은 대상에서 제외한다.
4. **운영 유지보수 자동화**: 인증 만료·무료 공급자 한도·디스크 사용량·장시간 무진행을 감지하고 기존 알림 경로와 연결한다. 성공한 백업의 보존 기간과 복구 검증을 정해 보관량도 자동 관리한다.
5. **수집 범위 확대**: 무료 공식 원천을 우선한다. 단일 기업 세그먼트/IPO/지원하지 않는 공시 형태는 성공으로 꾸미지 않고 전용 adapter와 검증 fixture를 추가한다. 현재 주기를 늘리기 전에 누락·오류·최신성 비율을 측정한다.

우선순위는 운영 복구·현재 변경 검증 → 1 → 2 → 3 → 4 → 5다. 후속 작업은 새 계약과 검증으로 진행하며 추천 scoring weight/benchmark/evaluation split을 바꾸지 않는다. PR #62/#63 운영 배포와 재무 자동 수집 검증은 완료했다. AI 순환 정책의 실제 모델 호출 검증과 기존 주의 항목은 별도이며, 모든 데이터/분석 품질이 정상이라는 의미는 아니다.
