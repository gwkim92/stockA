# 변경 검토

- 재무 period 선택은 원천 손익/현금흐름 수치의 존재, 보고일과 결산일 cutoff, normalized 존재를 모두 요구한다. 최신 유효 기간의 일부 결측을 옛 계산값으로 대체하지 않는다.
- 기존 period/financial fact 저장 오류, fiscal year와 분기 누적 문제는 수정하지 않았다. 입력 선택이 개선됐다고 원천 계산 품질을 승인하지 않는다.
- 비교군은 방법과 검증 범위를 추가하고 프롬프트 해석을 제한한다. peer 계산, scoring weight, benchmark, position, order 경로 변경 없음.
- 검토 기록은 정확한 보고서 내용 해시로 연결한다. 같은 ID의 다른 내용, 갱신된 보고서, fixture에 검토가 전이되지 않는다. 결과는 deep copy로 반환해 후속 소비자의 mutation도 격리한다.
- 화면에는 보완 필요만 기록한다. 완전 사실 검증이나 사람의 승인을 자동 부여하는 경로가 없다. HTTPS이며 credentials 없는 공식 링크만 렌더링한다.
- 데이터·문서 전체를 새 DB에 넣거나 원문을 대량 수집하지 않았다. 무료 원천 도입은 기간/출처 설계를 먼저 고친 뒤 별도 작업으로 진행한다.
- 잔여 위험: 원천의 최신 restatement가 과거 보고일에 연결된 문제까지 이번 SELECT가 해결하지 않는다. unknown report date는 입력에서 제외한다. 검토 기록은 코드에 보존한 한정 표본이며 범용 편집/승인 시스템은 아니다.
- 최종 CI와 운영 API/화면 검증을 통과했다. 운영 읽기 검증 전후 9개 보호 테이블의 전체 hash가 동일했고 환경/모델 설정도 유지됐다. 검증 범위를 데이터 전체 사실 정확성이나 과거 보고서 재생성까지 확대하지 않는다.
