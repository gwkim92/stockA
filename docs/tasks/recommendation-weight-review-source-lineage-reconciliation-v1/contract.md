# recommendation-weight-review-source-lineage-reconciliation-v1 Contract

## Task Request

- request: define one canonical recommendation-weight readiness → quality → outcome source lineage without rewriting legacy artifacts to make the shadow readiness result green.
- context: the deployed v2 shadow selected readiness `28`, latest quality `801`, and latest outcome `692`, but readiness `28` references quality `26` and outcome `27`. Independent latest selection therefore produced an intentionally fail-closed result.

## Goal

Add a read-only, append-only reconciliation artifact that anchors on one readiness audit and resolves the exact quality and outcome eval IDs referenced by that readiness artifact. Latest quality/outcome artifacts remain drift observations only. The artifact must version and hash the cohort-filter identity and the outcome nested-quality identity.

## Canonical Selection Contract

1. Select one readiness audit by explicit `readiness_eval_run_id` or, when omitted, the latest readiness artifact valid at the requested `as_of_date`.
2. Parse `source_eval_run_id` and `outcome_calibration_gate.eval_run_id` from that readiness score.
3. Resolve those exact eval IDs using the required eval name and dataset version. Do not substitute independently selected latest quality or outcome artifacts.
4. Select latest valid quality and outcome artifacts separately only to report lineage drift.
5. Build a versioned cohort-filter identity from the referenced outcome artifact's top-level and nested sample-audit filters.
6. Build a versioned nested-quality identity by hashing the exact referenced quality score and the quality score embedded in the referenced outcome artifact.
7. Fail closed when the anchor, references, source identities, dates, statuses, cohort filters, or nested-quality identity are missing or inconsistent.

## Invariants

- Existing v1 readiness, v2 readiness semantics, recommendation scoring, portfolio review, open-gate logic, and API payloads remain unchanged.
- Existing `ai.eval_run` rows are never updated, deleted, or regenerated by this task.
- Dry-run performs one atomic read and no writes.
- Execute writes only one `ops.pipeline_run` lifecycle and one append-only reconciliation `ai.eval_run` row.
- No migration is added.
- No user approval, pilot start, proposal, weight mutation, portfolio mutation, order, or broker-submit permission can be inferred from a reconciled lineage.
- Latest quality/outcome drift is diagnostic and never replaces the readiness-referenced chain.
- Future-dated source evidence is rejected at the SQL boundary and validated again in the pure builder.

## Acceptance Criteria

- The atomic lookup returns the readiness anchor, exact referenced quality/outcome artifacts, and latest quality/outcome observations from one Postgres statement.
- Referenced quality/outcome IDs must equal the IDs declared by the readiness score.
- Required source eval names and dataset versions must match exactly.
- Readiness quality/outcome statuses must agree with the referenced artifacts.
- Required cohort keys `market_code`, `strategy_name`, `horizon_type`, and `universe_version` must exist and match between top-level and nested outcome filters.
- The referenced outcome nested quality score must canonically hash to the exact referenced quality score.
- The artifact exposes a stable canonical-chain SHA-256 and separate versioned cohort/nested-quality SHA-256 identities.
- Missing references produce `lineage_incomplete_fail_closed`; inconsistent resolved evidence produces `lineage_incoherent_fail_closed`; a coherent chain produces `reconciled_read_only`.
- Latest-source drift is reported without changing the canonical chain or reconciliation decision.
- Every approval, pilot, mutation, order, and broker permission remains hard false.
- Focused unit tests, module CLI help, verification script, compile, migration diff, and diff checks pass.
