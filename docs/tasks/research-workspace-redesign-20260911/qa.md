# 검증 결과

## 완료한 검사

- TypeScript 타입 검사와 Next.js production build 통과.
- 웹 단위 검사 42개 파일, 523개 통과.
- 영향 브라우저 시나리오 160개: 기업·근거 48, 홈·공통 셸 30, 보유·성과 36, 뉴스·테마 46. 데스크톱·모바일을 포함한다. 마지막 원천 제목 스타일·동일 뉴스 설명 정리 후 관련 6개도 재확인했다. 원격 CI 결과는 아니다.
- 실제 운영 API를 GET으로만 읽는 로컬 production preview에서 핵심 6화면 × 2크기, 공통 영향 7화면 × 2크기: 26개 모두 HTTP 200, pageerror 없음, 문서 가로 넘침 없음. 별도 태블릿 768px의 기업 재무·뉴스·보유 3개도 넘침 없음.
- 원천 패널 데스크톱·모바일: 실제 RSS ID를 기존 읽기 경로로 조회했다. 금리 검색·선택·새로고침·닫기·초점 복귀를 확인했다. 해당 운영 원천은 발췌 목록이 비어 있고 한국어 요약만 존재하며, 화면에도 그대로 표시된다.
- 보유 MSFT 선택 후 새로고침 유지. 모바일 표는 문서 390px 안에서 컨테이너 358px, 내용 620px이며 ArrowRight 후 scrollLeft 40을 확인했다.
- AI 모델 설정의 기존 조회 경로를 유지했다. 로컬 GET 프록시에 실제 서버 비밀값을 복사하지 않았다. 로컬 표식 `local-get-only-preview`로 BFF의 연결 여부를 표시하며 원격 인증은 기존 EC2 환경에서 수행한다. 변경과 관리자 세션 생성은 로컬 프록시가 지원하지 않는다.

## 실패 후 수정

1. 새 기업 탭의 문맥 오류 검사는 다른 탭을 연 뒤 숨겨진 핵심 논리 링크를 찾았다. 핵심 논리 탭으로 돌아온 다음 동일 링크·잘못된 연결 부재를 확인하도록 동선을 수정했고 6개가 통과했다.
2. 모바일 보유 첫 행 y=801.8이 기존 780px 기준을 초과했다. 날짜 선택과 제목을 한 행으로 배치하고 요약 높이·안내를 줄였다. 기준을 완화하지 않고 재검사를 통과했다.
3. 새 홈 선택 검사가 서버 스트리밍 로딩 중 버튼 수를 즉시 읽었다. 첫 실제 검토 행의 표시를 기다린 뒤 URL·새로고침·뒤로가기·원래 순서를 검증했고 2개가 통과했다.
4. 초기 로컬 모델 화면에는 read token 표식이 없어 연결 미구성 상태가 나왔다. 실제 비밀값을 가져오는 대신 GET 전용 프록시와 같은 로컬 표식을 사용해 조회를 확인했다. 기존 Terra(gpt-5.6-terra), revision 2와 조회 전용 권한을 실제 화면에서 확인했다. 모델 설정은 수정하지 않았다.
5. 캡처 스크립트의 모델 화면 문구 대기는 현재 DOM의 문구와 맞지 않아 실패했다. 실제 표시 상태를 읽어 모델 조회와 캡처를 완료했다. 앱 기능 실패로 집계하지 않는다.
