# 배치 실행 자원 보호와 무진행 감지

요청: 서버 복구 후 다음 자동화 작업을 계속 진행한다.

## 완료 기준

- 실제 8GiB 호스트 사용량과 최근 7일 실행 시간을 확인한 뒤 배치 합산 메모리/CPU와 개별 작업 시간 상한을 적용한다.
- 하위 작업의 시간 초과가 자식 프로세스를 남기지 않고 실행 중/완료/중단 기록으로 확인된다.
- 현재 단계와 진행 시각을 원자적으로 기록하고 기존 scheduler-status 주기에서 기한 초과·중단·자원 제한 상태를 읽기 전용으로 판정한다. 조용한 정상 AI 호출을 로그 부재만으로 죽이지 않는다.
- 운영 API에서 실제 적용 상태를 읽고, 격리된 timeout/cgroup 실험 및 정상 재무 수집으로 웹/DB 응답·프로세스 정리·설정 보존을 검증한다.
- 기존 타이머와 인증/모델 설정을 보존하고 검증된 develop만 배포한다. 웹 변경이 없으면 기존 검증 빌드를 유지한다.

## 경계

개인 계정 115623963546의 기존 호스트만 대상. AWS 유형/요금/IAM/보안그룹은 바꾸지 않는다. 추천 weight/benchmark/schema/실거래/AI 추가 호출/외부 메시지는 대상 밖이다. 실행 결과가 불확실하면 자동 재실행하지 않는다. 배치 hard limit은 최후 방어이며 DB 변경은 컨테이너 식별/현재 사용량/백업 확인 후 가역적으로 적용한다.

현재 증거: 호스트 가용 6,834MiB, 최근 DB 완료 작업 최장 372초. 배치 resource/전체 timeout은 infinity다. 범위는 이번 운영 보호와 검증이며, 원천 버전 전파와 일반 단계 재개는 다음 작업이다.
