# 재무 원천 변경과 리서치 자동 갱신

사용자 요청: 서버 안정화 이후 자동화 작업을 계속 진행한다. 이번 범위는 성공적으로 갱신된 재무 원천을 기업 리서치 생성에 연결하는 것이다.

## 완료 기준

- 성공한 research_statement_refresh의 원본 SHA256와 기간 정책을 리포트가 읽은 재무 버전으로 저장한다. 실패한 수집은 새 버전이 아니다.
- 기존 research-maintenance와 daily 리포트 스케줄을 같은 갱신 실행기로 연결한다. 새 스케줄러/외부 알림을 만들지 않는다.
- 같은 원천/생성 정책의 완료 결과는 재호출하지 않는다. 전역 하루 5개 기존 한도 안에서 한 번에 최대1개를 실행하며 실행 전 DB 예약으로 동시 호출과 결과 불명 실행을 차단한다.
- 과거 또는 변경 중인 자료를 최신 자료로 주장하지 않는다. 기업 화면에 재무 입력 버전 일치/변경/미기록을 표시한다. 일치는 사실 검증이나 전체 시장 자료의 최신성을 뜻하지 않는다.
- 기존 atomic result receipt와 실제 artifact/invocation을 대조한다. 모델 실패·대체 결과·결과 불명은 각각 남기며 무조건 재호출하지 않는다.
- 원천 변경, 동일 원천 재수집, 실패 수집, 중복 실행, 할당량, 결과 불명, 생성 중 원천 변경, 정상 완료를 단위/실제 Postgres로 확인한다. 화면은 실제 브라우저로 확인한다.
- Linux CI를 통과한 develop과 외부에서 만든 웹 산출물만 운영에 배포하고 제한된 실제 canary·재실행 no-op·설정/보호 데이터 보존을 확인한다.

## 경계

추천 weight, benchmark, schema, 실거래, 모델 설정, AWS 유형/보안그룹/IAM은 변경하지 않는다. 기존 Codex OAuth 제공 경로와 하루5개 한도를 유지한다. 무제한 AI 생성/서버 웹 빌드는 하지 않는다. 원천/리포트 버전 연결은 재무 원천에 한정하며 기존 밸류에이션·뉴스·thesis 전체의 재계산 완료로 표시하지 않는다. 이전 중단 작업을 일반적으로 자동 재개하는 기능과 디스크 정리는 후속 작업이다.
