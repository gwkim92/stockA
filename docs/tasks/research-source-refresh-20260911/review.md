# 변경 검토

- DB lock을 별도 statement에서 획득한 다음 새 READ COMMITTED snapshot으로 예약한다. 같은 statement snapshot에서 오래된 한도를 읽던 위험을 실제 동시성 검사로 방지했다.
- 원천 성공 상태와 보고서 성공 상태를 분리했다. 저장 receipt와 artifact/invocation fingerprint가 맞는 primary 결과만 `current`로 판단한다. 불명 예약은 새 원천이 생겨도 해당 종목의 재호출을 막는다.
- 최근 성공한 수집의 원본 SHA/기간 정책을 context SQL snapshot과 manifest에 기록한다. 생성 중 자료가 바뀌면 기존 보고서의 버전을 덮어쓰지 않고 화면에서 변경 상태로 표시한다.
- 자동 경로는 두 스케줄에서 동일 worker를 호출하며 하루 5회, 회당 1회 제한을 공유한다. 기존 수동 리포트 CLI는 관리자의 별도 실행 경로로 남아 있고 자동 예약 lock을 직접 사용하지 않는다. 자동 일일 예산 계산에는 수동 OAuth 실행 기록도 포함한다.
- 확인된 fallback 저장은 24시간 뒤 기존 예산 안에서 재시도한다. receipt 없는 실패·결과 불명·사후 결과 변형은 무조건 재시도하지 않는다.
- 추천 규칙·금융 원천·schema·모델 설정·AWS 설정은 변경하지 않는다. 배포는 기존 외부 빌드 활성화 스크립트와 새 task checkpoint를 사용한다.

잔여 범위: 버전 연결은 재무 원천에 한정한다. 뉴스/밸류에이션 전체 freshness와 리서치 내용의 사실 검증을 증명하지 않는다. 불명 결과의 원인 확인 및 관리 복구는 후속 작업이며, 일반적인 자동 replay는 허용하지 않는다. 운영 canary는 일일 한도와 실제 OAuth 가용성에 따라 생성 검증이 제한될 수 있다.

운영 반영 후 검토: 실제 primary receipt와 추가 호출 없는 재실행, 보호 데이터 동일, 설정 보존을 확인했다. 배포 전 상태 수집기가 겹치는 실제 race를 발견하여 pause 뒤30초까지 기다리도록 보완했다. canary는 모델 호출 전 타이머 목록을 먼저 저장하고 ExecStopPost로 복원한다. 이 검증 도구 보완은 실제 배포/검증 실행으로 확인했으며 제품 코드나 투자 규칙 변경은 아니다.
