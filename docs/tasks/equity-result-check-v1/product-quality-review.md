## 판단

입력 오류, 근거 식별자, 기준일, 실패 처리, 저장 일관성을 보강한 방향은 타당하다. 그러나 현재 증거로 세계 최고 수준의 완성품이나 실전 투자 효용이 검증됐다고 평가할 수는 없다. 정확한 상태는 **개별 기능의 신뢰성 검증이 축적된 개발 중 투자 리서치 시스템**이다. 기술적 검증과 투자 분석 품질, 사용자가 느끼는 제품 완성도, 운영 배포를 따로 판단해야 한다.

원래 목적은 단순 주가 추천기가 아니다. 시장 변화 → 테마 사이클 → 기업 분석 → 투자 논리 → 보유 검토 → 성과 대조로 이어지는 중장기 투자 리서치 운영체계다. 따라서 "오늘 무슨 자료를 보고 어떤 판단을 다시 검토해야 하는가"를 읽고 행동으로 연결할 수 있어야 한다. 문서 수, 커밋 수, 테스트 수만으로 이 목적을 달성한 것으로 간주하지 않는다.

## 가장 중요한 평가상의 빈틈

기본 뉴스 평가 파일 `tests/fixtures/news_ai_eval_dataset_v1.json`의 `cases`는 현재 **5개**다. `src/stockanalysis/ingest/news/eval.py::score_news_ai_eval_dataset`은 각 사례의 저장된 `ai_output`을 파싱·검증한다. 해당 실행은 새로운 모델 답변을 생성하지 않는다.

따라서 이 평가는 작은 고정 사례에 대한 검증기 회귀검사다. 유용하지만 모델의 실제 최신 분석 정확도나 폭넓은 금융 판단 능력을 증명하지 않는다. 이번 task에서 데이터셋, 평가 기준, 추천 임계값을 바꾸지는 않았다. 267개 수준의 관련 코드 테스트도 이 5개 평가 사례와 성격이 다른 검사다. 서로 더해서 "모델 평가 표본"으로 보고하면 안 된다.

원문에 인용 문자열이 있다는 것과 분석 문장이 그 원문으로 충분히 뒷받침된다는 것 역시 다르다. 과거 날짜 필터가 있다는 것과 당시 알려진 정보만으로 완전히 복원했다는 것도 다르다. 이 구분은 후속 품질 보고의 필수 항목이다.

## 이번 개발의 제품적 의미

PR #40에는 저장 결과 대조 함수가 있었지만, 운영자가 직접 쓰는 진단 명령이 없었다. PR #41은 오류 보고의 run_id/request_hash를 받아 실제 저장 상태를 확인하는 읽기 전용 명령을 제공한다. 함수만 늘리는 대신 "불확실한 저장 결과를 어떻게 확인하는가"라는 한 사용 흐름을 끝까지 연결했다.

명령은 일치·불일치·미관측·확인 불가를 나누며, 어느 상태에서도 보고서를 다시 생성하거나 실행 상태를 고치지 않는다. 일치 결과를 투자 분석 정확도 또는 재실행 허가로 표현하지 않는다. 이것은 운영 진단 기능 완성이지 사용자용 리서치 제품 전체의 완성이 아니다.

## 다음 제품 마일스톤의 완료 기준

이 진단 기능 이후의 우선순위는 추가적인 범용 게이트나 상태 카드보다 **하나의 연결된 리서치 검토 묶음**이어야 한다. 허용된 원문·저장 분석에서 핵심 주장, 숫자의 통화/단위/기간, 반대 근거, 무효화 조건, 다음 확인 사항을 같은 맥락에서 대조하고, 뉴스에서 해당 기업·투자 논리·원천으로 왕복할 수 있어야 한다.

완료 근거는 실제 코드 경로의 화면 실행과 자료 대조다. 현재 값과 미확인 값, 원문과 모델 해석, 모델 실패의 규칙 기반 대체 결과를 구분해야 한다. 새 모델 실행·운영 데이터·비용이 필요한 평가는 기존 권한 범위 내에서 별도로 실행·관측해야 하며, 모의 결과로 대체했다고 숨기지 않는다. 동결된 정답 데이터나 평가 기준을 수정해서 점수를 높이지 않는다.

보유·주문·추천 가중치 변경은 이 마일스톤에 포함하지 않는다. 실거래 기능을 아직 만들지 않았다는 사실 자체는 현재 승인된 제품 범위의 실패가 아니다.
